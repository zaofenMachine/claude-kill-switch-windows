# 验收与证据口径

## 离线检查

```powershell
node --test tests/allowlist.test.mjs
python -m unittest discover -s tests -p 'test_*.py'
```

离线测试覆盖空名单、匹配节点、节点缺失、身份变化、重名、代理链、保留字、端口冲突、重复生成、独立脚本运行，以及 WFP XML 范围和基线比较。另有引擎启动门禁与 WFP 增量验证测试：保留已有集合、拒绝覆盖既有 EXE 策略、精确路径例外，以及拒绝缺失、改变或额外的过滤器。它们不安装真实 WFP，也不证明真实网络被阻断。

## 每台机器必须完成的无账号检查

1. **健康路径**：用出口测试页或 `check-proxy.mjs` 确认专用代理可用、出口符合预期。地区匹配不表示节点信誉已验证。
2. **路径覆盖**：核对运行中的 Desktop/Firefox 及保护清单中的辅助进程。采样 TCP 连接应指向专用入口；“没有采到连接”不是通过。
3. **受保护/普通对照**：使用同样编译内容的 ProtectedProbe 和 ControlProbe。只把前者纳入 WFP。先在自己控制的非回环测试接收端验证 ControlProbe 能连接，再验证 ProtectedProbe 被阻断。
4. **IPv4/IPv6 与其他端口**：各自运行对照。公网目标本身不可达时，将该项记录为证据不足，不能只因保护程序超时就判通过。
5. **UDP**：使用自己控制的接收端验证是否收到固定标记。UDP send 成功只说明发送调用返回，不能证明网络交付。
6. **故障恢复**：如确有需要，安排短暂故障窗口；独立恢复任务、回滚文件、时间上限全部准备好后再执行。不要依赖可能同时断网的远程助手恢复连接。
7. **持久化**：关闭 simplewall GUI 后检查过滤器仍在；下次正常重启后复查。不能把重启后的一次快照扩展为开机最早阶段保证。

探针用法：

```powershell
.\runtime\probe\ProtectedProbe.exe tcp 127.0.0.1 17987
```

其他目的地址及端口请使用自己的测试端点。返回值中 `socket-error` / `10013` 表示连接被权限拒绝；仍应配合实际 WFP CLASSIFY_DROP 事件关联具体规则。输出 `timeout` 不是阻断原因的证明。

## 高影响测试为何不直接提供启动按钮

原部署做过生产内核短暂退出、动态 WFP 阻断和版本拒绝实验，但脚本依赖私有恢复快照、安装版本、命名管道、进程路径及白名单。复制后直接运行可能无法恢复网络或应用。

如果重建故障测试，应先验证独立恢复任务，再使用只匹配指定应用和 `127.0.0.1:17987/TCP` 的动态过滤器。正常退出、崩溃退出都必须核实清理，正式持久化保护始终保留。读取 PowerShell 子进程退出码时，及时保留 `.Handle` 并先调用 `WaitForExit()`，避免空退出码被误判成失败。

## 原部署的脱敏证据摘要

这些是原机器的历史结果，不是公开版在所有机器上的承诺：

| 项目 | 已观察到的证据 | 限制 |
| --- | --- | --- |
| 持久化过滤 | 9 个目标路径对应 81 条持久化 BLOCK | 需要本机重新生成路径和审计 |
| 真实客户端故障 | Desktop 14 条、Firefox 5 条匹配临时规则的丢弃事件 | 脚本收尾异常使故障期间 TCP 采样未落盘 |
| 恢复 | 临时规则为 0，原规则内容一致；用户确认两端恢复 | 不是完整抓包验收 |
| 实际内核中断 | 6 项探针对照通过，6 条丢弃事件匹配，恢复成功 | 该次未同时覆盖全部真实客户端 |
| TUN 开启 | 保护探针专用端口可达；IPv4/IPv6 直连被拒绝，对照可达 | 不证明反复切 TUN 的整个过程 |
| 可选版本限制 | 曾实际验证拒绝激活，恢复后当前版本正常 | 未实际安装新版完成升级流程 |
| 后续内置引擎补齐 | 扩为 10 路径、90 条阻断；模拟新路径启动被策略拒绝（1260），当前引擎 --version 成功，用户确认会话正常 | 仅覆盖已确认的引擎根目录；未触发真实升级，详见 [引擎验收](engine-updates.md) |

原始 ERROR 记录没有被改成 PASS。后续复核分开保存，公开仓库仅保留上述摘要；完整 WFP XML、IP、账户信息、进程日志和截图不上传。

尚未据此宣称真实登录回调、开机最早阶段、系统 DNS 代发、全部辅助程序或全网卡零泄漏通过。不要将测试站的绿色评分当作这些缺项的替代证据。
