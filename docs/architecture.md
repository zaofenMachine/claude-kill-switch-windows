# 保护范围与架构

## 三层分别负责什么

1. **应用层**：Desktop 的 `egressProxyUrl` 固定为 `http://127.0.0.1:17987`；独立 Firefox 的 SOCKS5 代理、远端 DNS 等设置被锁定。
2. **路由层**：专用 listener 显式指定 Claude-Safe。白名单只存身份字段，不存订阅密码或 UUID；真实连接配置仍来自用户自己的订阅。
3. **阻断层**：按可执行文件的绝对路径安装持久化 WFP 过滤器。即使程序忽略代理、代理进程退出或系统代理关闭，其他目标地址/端口也应被阻断。

只有三层共同验证后，才能把指定程序视为已部署保护。单独看到代理出口正确、单独看到浏览器报错，都不足以证明阻断层有效。

Desktop 可能另行下载并启动 `claude-code` 引擎，它不一定位于安装包内，也不一定继承包身份。主包版本不变时，该引擎仍可更新。因此应额外核对实际进程路径和包身份，为当前引擎添加 WFP 路径规则，并用独立 EXE 路径门禁阻止未覆盖的新路径启动。见 [内置引擎更新保护](engine-updates.md)。

## 白名单行为

公开模板为空。生成器输出 `REJECT` 和当前订阅里符合精确身份的节点，不引用普通代理组、不加入 `DIRECT`、不自动选择最快节点。新增订阅不自动获得批准。

下列任一条件成立时，对应节点被排除：缺失、重名、与分组重名、类型/服务器/端口不匹配，或设置了 `dialer-proxy`。全部被排除时只留下 `REJECT`。生成器拒绝保留字、重复批准项及额外凭据字段。

身份字段匹配不等于节点信誉证明；同一个服务器域名也可能解析到不同出口。`expectedCountry` 仅供检查工具比较，不是持续在线的地理位置防火墙。节点出口换国家时不会自动触发 WFP 阻断。

分组为手动选择，连不上时不会自动换节点。内核可能保存选择；重载或切订阅后应核对当前分组，不能依赖某次旧选择始终保留。

## WFP 规则

生成器为每个已审阅路径关联四类出站阻断：

| 类别 | 阻断范围 |
| --- | --- |
| IPv4 | 除 `127.0.0.1` 以外的地址 |
| IPv6 | 全部 IPv6 地址 |
| TCP | 除 `17987` 外的有效端口 |
| UDP | 所有 UDP |

允许的是未被这些阻断覆盖的 **TCP `127.0.0.1:17987`**；其他防火墙仍可进一步拒绝它。四条 XML 规则在原 simplewall 版本中展开为每个程序九条 WFP BLOCK 过滤器，不能把这个数量硬套到任意工具版本。

不要添加“所有应用禁止出站”的全局规则来替代此设计，也不要把普通 Clash 端口、整个回环网段或其他程序的代理端口加入豁免。

## 明确未覆盖的情况

- 系统 DNS Client 服务代发、系统认证代理及由其他进程发出的请求，不一定匹配应用路径规则。
- 任意 MCP 子进程、Node/Python 工具、SSH 主机、WSL、Cowork 虚拟机及更新程序需要独立审计。
- 包名相同不表示新版本路径受保护。不能只凭包 SID、父进程关系或安装位置猜测覆盖范围。
- 引擎路径门禁只覆盖明确列出的根目录；安装器改变存储位置、程序被移动到其他位置、其他命名的进程或恶意本机代码仍需单独处理。它不是全机应用白名单。
- 未安装全机开机阶段的阻断规则；重启后观察到规则存在，不等于证明开机第一刻无流量。
- 无法防止管理员撤销规则，也不防其他本机进程冒用专用监听端口。
- 非 TCP/UDP 的回环协议不属于“只留代理 TCP 端口”的保证。
- Cloudflare/CleanIP 的地区、DNS 或 WebRTC 检测不能证明账号不会被限制；浏览器结果不直接代表 Desktop。
