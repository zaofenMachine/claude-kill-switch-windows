# 更新与回滚

## 节点维护

修改本机 `private/approved-nodes.json`，重新生成全局扩展并审阅后安装。检查生成配置及运行分组，并保留其他代理组选择、TUN、系统代理和订阅。若身份变化，先确认真实节点信息，再批准新身份，不要把精确匹配改成“名称包含某地区”。

`REJECT` 是默认项。切到其他订阅时，如果其中没有批准节点，专用组只剩 REJECT；普通代理还能上网，并不代表 Claude 通道可用。

不要把当前内存配置正常当成重启缓存正常。每次变更都确认全局扩展、当前生成缓存及运行态一致。

## Desktop 与浏览器升级

1. 记录当前安装版本、路径、签名及 WFP 基线。
2. 获取新包路径和全部实际联网程序清单，检查是否新增辅助进程。
3. 在新版本开始使用账号前，补齐对应路径规则并验证健康/阻断对照。
4. 更新版本限制后才允许新版本运行；正常重启并复核固定代理。
5. 旧路径只有在确认不会再运行时才能移除。

没有版本限制时，新包换路径可能先于规则维护启动。独立 Firefox 主程序的绝对路径即使未变，更新器或新辅助程序也需要审计。不要长期冻结有安全修复的旧版本，更新前安排保护维护。

## 可选 AppLocker 版本限制

原部署使用 Appx 规则集合：允许其他包，拒绝产品名为 Claude 的其他版本，仅对已经审阅的精确版本设置例外。由于当时的发布者匹配问题，拒绝范围是所有发布者下产品名为 Claude 的包；这是需要评估的取舍，不是通用推荐模板。

本仓库不分发那份可直接执行的策略，也不固定任何用户的包版本。自行准备时：

- 先导出本地和有效策略，检查管理来源、Windows 版本/版本类型和 AppIDSvc 状态。
- 用安装包的真实身份生成候选；不要照抄旧版本字符串或别人的规则 ID。
- 对本机可评估包执行 `Test-AppLockerPolicy`，逐项检查允许/拒绝结果及未评估对象。
- 已有其他 AppLocker 策略时进行合并，不能用只包含本项目规则的 XML 覆盖整机策略。
- 若做真实拒绝实验，先关闭客户端并准备独立恢复入口和超时恢复；恢复后必须实际验证可启动。

离线评估成功不能替代实际生效验证。参考 [Microsoft 的打包应用规则说明](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/applocker/manage-packaged-apps-with-applocker)。

## 撤销顺序

这是针对自己部署记录的人工恢复清单，不是“导入别人整机备份”的指令：

1. 保存工作并关闭 Desktop、专用 Firefox 和已保护辅助进程，暂时保持代理内核可用。
2. 如果专用 Firefox 仍是默认浏览器，在 Windows 设置里先选回普通浏览器。再执行：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\Register-ClaudeBrowser.ps1 -Mode Remove -ValidateOnly
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\Register-ClaudeBrowser.ps1 -Mode Remove
   ```

3. 按本机原记录恢复 Desktop 的代理值及类型。原先没有这个值才删除它，保留其他策略键值。
4. 如启用了版本限制，只移除自己拥有的规则，并恢复确需恢复的服务启动配置；保留后来新增的其他策略。
5. 在当前订阅基础上合并移除专用 listener、Claude-Safe 和自己添加的域名规则；检查其他规则是否仍引用该组。恢复/合并原全局脚本，校验并同步生成缓存。不要用最初的旧订阅覆盖后来更换的订阅。
6. 最后移除自己拥有的 WFP 阻断；若 simplewall 也管理其他规则，只删除本项目关联，不能直接卸载整个 provider。复查其他网络行为。

不导入整机防火墙快照覆盖现状，也不关闭安全软件。保留备份直到恢复验证完成。

专用 Firefox 文件和 profile 不会随撤销注册而删除；其锁定策略仍指向专用入口。撤销部署后应使用普通浏览器，或在明确放弃专用保护后单独处理这份配置。

## 故障排查

| 表现 | 先检查 |
| --- | --- |
| 普通网站能用，Claude 无法连接 | Claude-Safe 是否选中 REJECT、是否有匹配的批准节点、17987 是否监听 |
| 换订阅后只剩 REJECT | 新订阅没有精确匹配节点，属于预期拒绝 |
| 提示管理员阻止应用 | 当前版本是否被 AppLocker 版本限制拒绝；不要先删除 WFP 来试错 |
| 浏览器启动器拒绝启动 | Firefox 路径、策略文件原始字节及构建来源；不要跳过哈希校验 |
| 旧错误页一直显示代理失败 | 先确认临时故障已解除，再刷新；旧标签页不一定自动重载 |
| 出口测试不符合预期国家 | 记录本地证据，停止使用该节点并自行检查；地理位置不会被白名单持续强制 |
