# 订阅管理与更新

主窗口或托盘中的「订阅管理 / 更新」用于保存多份 Mihomo 订阅。每次使用一份来源，与 Clash 的配置列表类似；它独立保存配置，不读取或改写 Clash Verge 的订阅、当前组选择或 TUN。

## 添加、更新和使用

1. 点击「添加订阅」，输入便于识别的名称和 HTTPS 订阅地址。首次下载和解析成功后保存为未使用的订阅，当前通道保持原样。
2. 选择订阅后可「更新所选」，也可「更新全部」。失败的订阅保留上次成功的节点缓存，其他订阅仍可更新；列表显示上次成功时间和本次错误。
3. 点击「使用所选」切换节点来源。切换会停止专用内核并保持 REJECT；回到主窗口审阅节点批准状态，再手动启动内核、选择批准节点和检查出口。
4. 更换地址只替换保存的下载地址；使用「更新所选」成功获取后才更新缓存。可以重命名或删除订阅。删除正在使用的来源会停止内核并清空当前来源，批准名单保留。

主窗口保留本地 YAML/JSON 导入，适合下载后离线导入。它创建并使用一份本地配置；本地配置没有可更新的 HTTPS 地址。订阅窗口关闭不会停止内核。

## 更新时的连接行为

| 操作 | 当前专用通道 |
| --- | --- |
| 新增订阅、更新未使用的订阅、重命名或替换下载地址 | 保持当前通道 |
| 正在使用的订阅下载失败、格式无效 | 保留上次成功内容和当前通道 |
| 正在使用的订阅更新成功，节点内容没有变化 | 保持当前通道 |
| 正在使用的订阅更新成功，节点内容发生变化 | 停止专用内核，审阅后手动恢复 |
| 使用另一份配置、删除正在使用的配置 | 停止专用内核，保持阻断 |

订阅下载与解析先完成，之后才应用；失败不会用空配置覆盖上次成功内容。更新不自动扩大批准名单，也不自动选择新增节点。同名节点只有名称、类型、服务器、端口与现有批准身份完全匹配且通过结构检查，才可用于专用通道。地址或端口等身份变化需要明确重新批准。

只解析订阅内的 `proxies` 叶节点。不执行订阅脚本，不继承其代理组、路由、TUN、管理端口、`proxy-providers` 或其他程序设置；仅含 provider 的配置需先转换为含实际叶节点的 Mihomo YAML/JSON。重复节点名称会拒绝该次导入，不混合多份订阅的同名节点。

## 下载与本机保存

下载使用 Windows 的系统代理设置，便于沿用日常 Clash 系统代理。此设置只用于获取订阅文件；Claude 专用内核的出站网卡、固定入口和阻断规则保持独立。没有另设 DIRECT 回退或通过专用 Claude 入口下载的逻辑。

仅接受无用户信息、无片段的 HTTPS 地址，正常验证 TLS，不跟随重定向，不携带账号 Cookie。若服务返回跳转，应从服务方取得最终 HTTPS 配置地址，或下载为 YAML/JSON 后本地导入。单次下载整体上限 30 秒、16 MiB；最多保存 32 份来源。这里提供手动更新所选或全部订阅，不自动定时拉取订阅；Desktop 定时测速是另一项设置。

名称、下载地址、更新时间和完整节点缓存在本机数据目录的 `subscriptions.json`。地址可能包含账户令牌，节点缓存包含连接凭据；列表只显示来源主机，替换地址时输入新地址。不得把数据目录上传 GitHub 或贴到 Issue。

旧版本首次升级时，把现有 `source.json` 迁移为正在使用的本地配置，保留当前节点和 `settings.json` 的批准记录。此后以 `subscriptions.json` 为准，旧 `source.json` 留作迁移输入；不继续编辑它来维护现有订阅。目录损坏时拒绝加载，不回退到过期的来源。请在停止管理器后备份整个数据目录，再恢复匹配的配置。

离线回归：`dotnet run --project app/ClaudeSafe.Manager.SubscriptionTests -c Release`。默认不访问真实订阅服务，不运行客户端或修改系统网络设置。
