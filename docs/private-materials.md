# 未上传的内容与本机准备方式

公开仓库从经过审阅的文件清单建立，未将原工作目录整体纳入 Git。运行目录、备份和测试报告全部忽略，不能用 `git add -f` 绕过。

| 未上传内容 | 原因 | 本机替代方式 |
| --- | --- | --- |
| 完整订阅、URL、UUID、密码、Clash 生成配置 | 含连接凭据、账户信息及全部订阅 | 从自己的服务来源导入，保存在本地；不随项目分发 |
| 实际节点名单、域名、IP、订阅 UID | 暴露用户网络与服务信息 | 填写 `private/approved-nodes.json`，仅使用必要身份字段 |
| 全局扩展的实际生成版 | 嵌入真实批准节点 | 用空模板和生成器在本地创建 |
| Firefox profile、Cookies、登录缓存、认证链接 | 可能含账号会话及个人浏览数据 | 创建全新独立 profile，不复制示例用户资料 |
| Claude 日志、原始截图、进程/TCP/WFP 导出 | 可能出现路径、用户名、IP、账号信息、访问内容 | 验收时写本地私有目录；分享前逐项脱敏 |
| simplewall/Mihomo/Firefox/Claude 二进制和安装包 | 第三方许可、版本和供应链管理 | 从官方来源下载并核验；仓库只编译自己的辅助程序 |
| 实际 AppLocker XML 和恢复快照 | 与本机版本、策略、服务状态绑定 | 按维护文档重新审阅并生成；先备份再启用 |
| 内置引擎批准记录、实际缓存路径、签名/哈希清单及 EXE 门禁 XML | 含本机用户目录和安装布局 | 用 Inspect-DesktopRuntime 与 engine_gate 在本机准备；发布仓库只留空模板和生成器 |
| 原环境的安装、移除、订阅扩展及缓存同步脚本 | 固定路径、旧备份基线和特定订阅，跨机器可能误覆盖 | 公开生成器只准备配置；按部署文档人工应用和审计 |
| 整体 Clash 中断和动态 WFP 故障脚本 | 涉及管理员权限与本机恢复边界 | 按测试文档重建并独立验证恢复，不直接复制旧现场逻辑 |
| WindowsApps 路径、包清单、编译器路径快照 | 每台机器及版本不同 | 使用 Inspect-Desktop，并在本机选择实际工具路径 |

没有上传源码的高影响流程，其设计、前置条件、验收口径和恢复顺序分别保留在 deployment、testing、maintenance 文档中。不会伪装成已完成跨机器验证的一键工具。

## 发布前检查

1. `git diff --cached --stat` 和 `git diff --cached` 审阅将要上传的每个文件。
2. 运行 `python scripts/check-publication.py`。它读取索引中的精确内容，拒绝常见私有目录、二进制、用户目录、令牌和含凭据 URL。
3. 人工搜索真实节点名、服务器、账户、邮件、订阅 URL、访问令牌、认证回调、截图中的 IP，以及工作目录绝对路径。
4. 确认没有将备份、配置转储或旧 Git 历史推上去。`.gitignore` 只影响未跟踪文件，不能清除已提交的秘密。

此检查是有限规则匹配，不是完整安全扫描。公开 Issue 中不要贴完整配置和日志；只提供脱敏结构、错误代码、版本及已完成的对照步骤。

## 发布与本机部署是两份目录

仓库的模板和公开工具不包含任何正在运行的本机策略。对公开源码的测试不会自动更新已安装的全局扩展、WFP、AppLocker 或默认浏览器。将修改带回实机前仍需按部署步骤审阅。
